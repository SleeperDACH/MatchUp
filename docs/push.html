1 Apple-Mitgliedschaft auf diesem Mac Pflicht · 10 Min

Warum: Ohne bezahltes Team darf die App keine Push-Benachrichtigungen verwenden, und es gibt kein Distribution-Zertifikat — derselbe Grund, aus dem flutter build ipa scheitert.

  1. Xcode öffnen.
  2. Menü Xcode → Settings… (oder ⌘ + ,).
  3. Reiter Accounts.
  4. Unten links auf + → Apple ID → Continue.
  5. Mit der Apple ID anmelden, die zum bezahlten Team HACJC6623Z gehört.
  6. Links das Konto anklicken. Rechts muss MatchUp (HACJC6623Z) stehen — Rolle Account Holder, Admin oder App Manager.
  7. Rechts unten Download Manual Profiles.
security find-identity -v -p codesigning
Fertig, wenn dort eine Zeile mit Apple Distribution steht. Steht weiterhin nur Apple Development, bist du im falschen Team angemeldet oder die Mitgliedschaft ist abgelaufen — das ist der Stand von heute.
2 Push für die App-ID einschalten Pflicht · 3 Min

Warum: Apple muss wissen, dass genau diese App Push benutzen darf. Ohne das Häkchen trägt das Provisioning-Profil kein aps-environment, und APNs weist jede Nachricht ab.

  1. developer.apple.com/account öffnen, anmelden.
  2. Oben rechts prüfen: Steht dort MatchUp / HACJC6623Z? Sonst umschalten — mit dem persönlichen Team gibt es die Option nicht.
  3. Links Certificates, Identifiers & Profiles → Identifiers.
  4. In der Liste app.matchup.mobile anklicken.
  5. Häkchen bei Push Notifications setzen.
  6. Oben rechts Save, Rückfrage mit Confirm.
  7. Danach in Xcode noch einmal Download Manual Profiles — sonst baut Xcode weiter gegen das alte Profil ohne Push.
Fertig, wenn neben Push Notifications ein Häkchen steht und die Seite Enabled anzeigt.
3 Die Schlüsseldatei .p8 erledigt
Steht seit dem 24.09.2026: ~/keys/AuthKey_9JF35BFS9Q.p8. Die Anleitung bleibt stehen, falls der Schlüssel je ersetzt werden muss.

Warum: Sie ist der eigentliche Schlüssel. Key ID und Team ID sind nur die Kennnummern dazu.

Apple gibt eine .p8 nur einmal heraus. Ist sie weg, legst du einen neuen Schlüssel an: developer.apple.com/account → Keys → alten Revoke → + → Name MatchUp Push → Häkchen APNs → Continue → Register → Download. Die neue Key ID notieren und mir sagen.

6 APNs-Schlüssel bei Firebase hier hängt es
Am 04.10.2026 gemessen: Der Schlüssel greift nicht. Ein Testpush an das registrierte iOS-Gerät scheitert mit HTTP 401 · Invalid APNs credential (THIRD_PARTY_AUTH_ERROR).
Was das heißt: FCM hat den Geräte-Token angenommen — sonst käme UNREGISTERED — und ist dann bei Apple abgewiesen worden. Der Fehler sitzt zwischen Firebase und Apple. Die Datei auf dem Mac ist dabei in Ordnung: gültiger privater Schlüssel, 256 Bit, 257 Bytes. Nachzusehen ist zweierlei: ob bei Firebase die Key ID 9JF35BFS9Q und die Team ID HACJC6623Z stehen (es gab einen Vorgänger 8887U4P9BH) — und ob der Schlüssel bei Apple noch aktiv ist und nicht auf Revoked steht.

Warum überhaupt: Firebase spricht in deinem Namen mit Apple. Dafür braucht es die .p8 samt Kennnummern.

  1. Firebase-Konsole → Zahnrad → Projekteinstellungen → Reiter Cloud Messaging.
  2. Abschnitt Apple-App-Konfiguration, bei app.matchup.mobile: APNs-Authentifizierungsschlüssel → Hochladen.
  3. Datei: die .p8 aus ~/keys/. Key ID: 9JF35BFS9Q. Team ID: HACJC6623Z.
